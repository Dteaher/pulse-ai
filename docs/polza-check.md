# Подключение Polza: проверка 14.10.2026

Работа выполнена в отдельной ветке `codex/polza-provider` нового репозитория. Оба production `.env` сохранены без изменений, их контрольные суммы до и после реальных запросов совпали. Деплой и push не выполнялись.

## Что изменено

- Добавлен PolzaProvider поверх общего OpenAI-compatible транспорта. DTO, Normalizer, Validator и Builder не изменены.
- Polza передаёт рассуждение через `reasoning.effort`; MultiAI сохраняет `reasoning_effort`.
- Добавлен официальный адрес Polza в factory; модели выбираются настройками.
- Единая таблица сопоставляет токены и reasoning для операций и их aliases. `preparation_v2` теперь наследует parse-настройки.
- `LLM_BUSINESS_COVERAGE_REASONING_EFFORT` отделён от Doctor; пустое значение наследует общий reasoning.
- Телеметрия сохраняет фактически использованный response_format, response_model, reasoning_tokens и cost_rub, когда API возвращает эти поля.
- `.env.example` содержит инструкции Polza → MultiAI. Сценарий без ключей остаётся mock; рабочие настройки автоматически не переключались.

## Реальные проверки

По уточнению владельца выполнены ровно шесть генераций: один запрос каждого размера на каждом провайдере. Cache и автоматический fallback выключены для сравнения маршрутов; reasoning low, output budget 8000, timeout операции 90 секунд, общий deadline 240 секунд. Использован настоящий HTTP транспорт провайдеров и полный FastAPI pipeline внутри ASGI.

| Сценарий | Провайдер / модель | Время, с | HTTP PULSE | BPMN |
|---|---|---:|---:|---|
| Простой | Polza / openai/gpt-6-luna | 33.95 | 200 | Получен |
| Простой | MultiAI / gpt-5.5 | 10.73 | 502 | Timeout |
| Средний | MultiAI / gpt-5.5 | 114.64 | 502 | Timeout extraction после успешного preflight |
| Средний | Polza / openai/gpt-6-luna | 31.64 | 200 | Получен |
| Сложный | Polza / openai/gpt-6-luna | 50.79 | 200 | Получен |
| Сложный | MultiAI / gpt-5.5 | 34.75 | 200 | Получен |

Это шесть генераций, но 11 реальных API-вызовов: обычно preflight + extraction; простой MultiAI оборвался на первом вызове. HTTP 502 здесь относится к PULSE, а не к HTTP-ответу внешней модели: timeout не имеет внешнего HTTP status.

Polza: **0.77586643 ₽**, шесть HTTP API-вызовов с полным usage/cost_rub. Ни одного дополнительного платного повторения ради статистики. MultiAI: известно 7 482 входных и 4 584 выходных токенов успешных ответов; стоимость и расход оборвавшихся запросов API не сообщил. Эти значения нельзя считать полным биллингом кабинета.

XSD и внутренние валидаторы не ослаблялись. Для успешных результатов сравнение normalized ProcessDefinition → XML не выявило различий. Независимые проверки подтвердили направления XOR, условия, исполнителей, AND split/join, возврат исправленных документов и договора, два Pool и 4/5 MessageFlow. Нормализация Polza среднего/сложного результата добавила явно отмеченный XOR merge перед event-based ожиданием, перенаправив два входа; действия и исходы сохранены.

Три схемы Polza импортированы и отрисованы настоящим bpmn-js в Edge автоматизированными браузерными тестами; все узлы найдены на полотне. Скриншот сложного процесса визуально просмотрен. Результаты и traces находятся в `.runtime/polza-check/`, ключей в отчётах нет.

## Надёжность и ограничения

Mock-тестами подтверждены Polza → MultiAI при timeout, network error, 429 и 500/502/503/504. Общий набор также проверяет corrective retry, оба провайдера недоступны, cooldown, общий deadline и Vertex fallback. Новые тесты проверяют отмену cache owner/waiter и освобождение singleflight.

Весь backend-набор: **544 passed**. Браузерная проверка реальных схем Polza: **3 passed**.

Новый провайдер не меняет существующие браузерный timeout 500 секунд и Caddy response_header_timeout 500 секунд. Реальный предел ingress Amvera в публичной документации не подтверждён; утверждать совместимость произвольного долгого запроса с Amvera нельзя. В тестовой конфигурации backend deadline 240 секунд меньше локального proxy/browser timeout. Production конфигурация и архитектура фоновых задач не менялись.

Разделённую provenance генератора и business reviewer в API metadata в этом сокращённом проходе не добавляли. Business coverage в платной проверке выключен для экономии; тест не доказывает его реальную работу на Polza. Настоящее переключение после искусственно вызванного сбоя с дополнительным платным fallback запросом не выполнялось: резервный маршрут проверен независимо, переключение — mock-тестами. Одна успешная генерация каждого размера не даёт статистически надёжной оценки median/p90.

Вывод: Polza Luna работоспособна в этих трёх процессах. MultiAI GPT-5.5 работает, но сейчас нестабилен по ожиданию ответа; его нельзя считать гарантированно доступным резервом. Рабочий `.env` нового проекта пока остаётся прежним — автоматического production переключения не было.
