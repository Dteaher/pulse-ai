# Этап A: детерминированный BPMN Doctor

Новые правила работают без LLM. DOCTOR_LLM_AUDIT_ENABLED=false по умолчанию; старый необязательный AI-аудит сохранён за флагом. BPMN_FORMAL_MESSAGES_ENABLED=false и DOCTOR_EXECUTION_PREPARATION_ENABLED=false. Концептуальные процессы остаются isExecutable=false. Исполнение в движке не проверено, этапы B/C не выполнялись. Рабочие .env, ключи и Amvera не изменены.

Диагностика Doctor содержит code, category (notation/execution/business/readability), severity, element_ids, description, reason, suggestion, confidence. Старые поля сохранены. clarification преобразуется в warning только в ответе Doctor. Находки не изменяют процесс. confidence — качественная оценка эвристики, не статистическая вероятность.

Правила: достижимость, SCC с различием циклов с выходом и закрытых циклов, ожидание сообщений без показанного таймера, риск AND join без предшествующего AND split, отдельные параллельные завершения, риск Terminate End в параллельной ветви. Под флагом подготовки: неформальное условие XOR и риск отсутствия default. Default и таймер не объявляются обязательными для любой BPMN. Проверки токенов эвристические: наличие split не доказывает отсутствие блокировок; SCC не доказывает бесконечность. Анализ ограничен 150 FlowNode на Process, больше — явная информация о неполной проверке. Данные, внешние запуски, гарантированное выполнение задач и внешние таймауты не анализируются.

Doctor больше не сообщает ложные ошибки графа/участников для корректного XML вне AI subset: статус частичной проверки. Структурный PARALLEL_JOIN_MISMATCH в Doctor — предупреждение с пояснением; production Validator/Builder не ослаблены. Неподходящие типы sourceRef/targetRef/flowNodeRef теперь выявляются и до остановки расширенной семантики.

Формальные сообщения выводятся из существующих MessageFlow: стабильные уникальные bpmn:message, messageRef на MessageFlow, на send/receive task и message event при однозначном соответствии. Для нескольких разных сообщений на одном endpoint не выдумывается один messageRef. Никакие itemRef, схемы payload, реализации API или корреляция не создаются. PULSE-owned определения помечены provenance; собственный импорт принимает только точно восстанавливаемые определения и проверяет стабильные ID, названия и привязки. Изменённые/внешние определения остаются за пределами AI subset, доступны для ручного XML-редактирования. Перед AI импортом производные определения разворачиваются обратно в MessageFlow; при включённом флаге воспроизводятся. Это не общая поддержка произвольных внешних формальных сообщений.

Проверки: 20 новых backend test cases; полный backend — 612 passed (один TestClient deprecation warning). 17 выбранных браузерных тестов Edge passed: новый Doctor, plain/formal imports, редактор, экспорт, Clarify, Modify, Undo/history и прежние conformance cases. Два новых browser cases затем повторены после исправления текста выключенного LLM-аудита. Типизация и сборка frontend прошли; Vite предупреждает о существующем крупном чанке Modeler. SIMPLE/MEDIUM/COMPLEX стандартный XML побайтно совпал с Builder из HEAD. Платных запросов нет.

Риски: эвристики могут давать предупреждения для корректных неструктурированных графов; полная токеновая корректность не доказана. Стандартная генерация сохраняет прежний subset; flag-enabled message declarations требуют сохранения флага для регенерации. Прямой /bpmn использует значение XML-флага при старте приложения; после изменения профиля перезапустите backend. Новые детерминированные рекомендации могут увеличить длину панели, она проверена в браузере со скроллом. Конкретные движки, переменные и исполняемые интеграции не реализованы.
