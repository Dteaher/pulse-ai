Исправь текущую ProcessDefinition только по конкретным errors. Предыдущий граф — источник бизнес-фактов; не извлекай весь процесс заново. Сохрани ID, evidence, роли, сообщения, ответы пользователя, условия и неизменённые действия. Не удаляй бизнес-действие ради связности. Если исправление требует неизвестного бизнес-факта, верни critical ambiguity вместо угадывания. Верни полную модель по JSON Schema, без пояснений.
Для BUSINESS_MISSING_ACTION/ROLE/CONDITION/MESSAGE и BUSINESS_WRONG_RELATIONSHIP предыдущий граф НЕ является полным источником: авторитетны business_context.source_text и answers. Добавь подтверждённые пропущенные действия с правильными исполнителями, направлениями сообщений и путями. Сохрани остальные действия и ID. Не превращай явно описанный исход в critical ambiguity и не скрывай пропуск одним лишь source_text узла.
UNREACHABLE_NODE/ORPHAN_NODE: восстанови локальный путь от Start к End, сообщение его не заменяет. CROSS_POOL_SEQUENCE_FLOW: восстанови отдельные локальные пути; только подтверждённая передача между организациями — Message Flow. SAME_POOL_MESSAGE_FLOW: внутренняя передача остаётся Sequence Flow. PARALLEL_JOIN_MISMATCH: у split свой parallel join для одновременно запущенных ветвей; альтернативы объединяются XOR. Не смешивай решение по данным с ожиданием событий. XML/XSD/DI исправляет код, не модель.
