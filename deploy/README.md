# Запуск PULSE на сервере

Нужны Docker Engine с Compose, домен с A/AAAA на сервер и доступные порты 80/443. До запуска создайте `.env` в корне проекта по `.env.example`, укажите ключи и `SITE_ADDRESS=pulse.example.org` (замените своим доменом). Не добавляйте протокол для публичного HTTPS. Сертификат выпускает и продлевает Caddy; его состояние сохраняется в volume `caddy_data`.

```sh
docker compose up -d --build
docker compose ps
curl --fail https://pulse.example.org/api/health
```

Frontend и `/api` используют один HTTPS origin. Backend не публикует порт наружу. Прокси допускает до 500 секунд ожидания заголовков ответа. Backend применяет общий бюджет 450 секунд на анализ, генерацию, проверку полноты, исправления и failover; frontend и прокси допускают 500 секунд. Это максимум ожидания, а не целевое время: модельная проверка увеличивает задержку. Для локальной проверки без сертификата: `SITE_ADDRESS=http://localhost`, тот же запуск, откройте `http://localhost`.

Compose передаёт `.env` как окружение контейнера. На PaaS можно вместо него задать переменные в секретных настройках сервиса: окружение имеет приоритет над файлом. Контейнер backend по умолчанию работает без root, в production-режиме, без raw debug. Ключи не копируются в образы. Frontend получает только собранные публичные файлы. Изменив ключи или модель на сервере, выполните `docker compose up -d --force-recreate backend`.

На PaaS с отдельным backend направьте `/api/*` на него через свой reverse proxy без удаления префикса `/api`. Не используйте Vite dev server или preview как production-сервер. Настройте startup command `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`, working directory `backend`, зависимости `backend/requirements.lock.txt`.

Проверка полноты включена: отдельный типизированный LLM-запрос сравнивает кандидата с оригинальным текстом и ответами Clarify. Доказанные пропуски блокируют экспорт и поступают в ограниченный corrective retry. Проверка увеличивает время и расход токенов, использует тот же deadline и failover; она модельная, не является формальным доказательством полноты. Для диагностического сравнения можно отключить `LLM_BUSINESS_COVERAGE_ENABLED=false`.

Вход пользователей и ограничения расхода API намеренно не добавлены по текущему запросу. Поэтому этот запуск предназначен для контролируемого демо; ограничения доступа при необходимости настраиваются отдельно. Генерация может завершиться безопасной ошибкой при сбое моделей или исчерпании бюджета. Финальные сертификаты и доступность домена проверяются только после запуска на выбранном сервере.

Обновление: `docker compose up -d --build`. Просмотр журнала: `docker compose logs --tail=100 backend web`. Остановка: `docker compose down` (без `-v`, чтобы сохранить сертификаты).
