# Один сложный процесс: MultiAI и Polza

Один и тот же complex golden text, четыре генерации, reasoning low, cache off. MultiAI вызывается реальным резервом LLMRouter после тестового timeout Polza; явная схема только для резерва, output token cap не отправлялся. Polza запускается как основной провайдер без этой настройки и с обычным лимитом 8000 output tokens. Поэтому сравнение оценивает рабочие маршруты, а не идентичные параметры API. Рабочие .env и Amvera не изменялись.

| Маршрут | Время | BPMN | Строгая проверка |
|---|---:|---|---|
| MultiAI gpt-6-luna | 80,81 с | Нет | Разрывы графа после corrective retry |
| MultiAI gpt-6.1-sol | 65,81 с | Да | Не прошла эталон отдельных действий |
| MultiAI claude-opus-5 | 79,89 с | Да | passed |
| Polza openai/gpt-6-luna | 54,60 с | Да | passed |

Luna: provider_output содержит c_wait2 без исходящих связей; corrective output также co_check без исходящих связей. В обоих normalization changes=[]; Builder не запускался. Это ошибки графа, уже присутствовавшие в ответе модели.

Sol: строгий evaluator остановился на названии «Ожидать исправленные документы» вместо «Получить…»: receive_task семантически может представлять получение, поэтому одно название не доказывает потерю действия. Дополнительно ручная проверка показала объединение «Доработать договор и повторно передать руководителю» в один task, тогда как эталон требует отдельных действий. Полное соответствие эталону не подтверждено. Синтаксические валидаторы и Builder прошли.

Opus и Polza: шесть ролей, отдельные действия, XOR исходы, AND split/join, два цикла с правильным первым действием возврата, событийное ожидание, пять MessageFlow, XML fidelity — passed. Все три полученные XML импортированы в bpmn-js в Edge; все узлы отображаются, ошибок страницы нет. Первоначальный browser harness ошибочно требовал резервную отметку и для primary Polza; проверка исправлена в соответствии с metadata, Polza повторно проверена без платного запроса.

Итого 9 реальных POST (3+2+2+2); Polza cost_rub=0.4875901, расход MultiAI в рублях неизвестен. Polza выполнена ровно один раз. Один прогон не устанавливает статистическую стабильность. По этой выборке Polza быстрее и полностью проходит эталон; Opus — наиболее успешный резерв из трёх проверенных на этом сложном тексте.
